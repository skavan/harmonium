Why a swatch, not just the phone
The phone shows the whole page; the swatch shows the one button at kiosk scale next to its neighbours. Width decisions are relative — you're choosing how many fit a row, and the row-budget meter says so in words.
Yes — tabs everywhere
Activities, presets, devices and doorways all open into the same card with the same tab bar. Learn it once on an activity and you already know how to edit a preset.
Appearance is always second-to-last
Every item type has it, always in the same position, always the same controls: label, icon, accent, width, height, state line. Muscle memory beats discoverability.
Width needs a ruler
Abstract fractions mean nothing on a 5″ screen, so the tab carries an actual-size swatch and a row-budget meter. That's the layout complexity made legible without a canvas editor.

Structural move
An activity becomes its own page reached from the rail, edited as a numbered four-step flow with a Next button. The overloaded scroll is gone; each step fits without scrolling.
Tone
Cobalt is the interface signal; amber is reserved for activity identity, so the Studio stops competing with the remote's own colour. Empty states get first-class cards.
Risk
The wizard suits first-run better than the tenth edit — it needs a "show all steps" escape for power editing, and it's the largest deviation from the current interaction contracts.
