# Config Guide — what makes each page

Everything you see is produced by TWO files in `www/remote-proto/`:
`index.html` (the engine — no house data) and `config.json` (pure
data). This guide maps each page on the remote to the config that
creates it. Current version: **v17**.

## The one big idea

Screens you author live in `screens:`. **Device detail pages are NOT
in the config at all** — they are generated by the engine from the
entity's own attributes when you tap a tile's ⚙ trailing zone
(`detail:<entity_id>`). You only configure *exceptions* (via
`entity_options`) — never the pages themselves.

## Top-level map

```jsonc
{
  "version": 17,
  "entity_options": { ... },   // per-entity display quirks
  "theme": { ... },            // design tokens → CSS variables
  "devices": { ... },          // device profiles (capabilities + keymap)
  "keymap": { ... },           // fallback physical-key table
  "home_screen": "home",
  "screen_order": [ ... ],     // ◀▶ paging order at grid edges
  "global": { ... },           // room name, main_home, VOL bindings, activity_select
  "activities": { ... },       // scripts + screen + context per activity
  "screens": { ... }           // the authored pages
}
```

## Porch home page

`screens.home` — 1-column (tiles render as list rows), with a hero:

```jsonc
"home": {
  "name": "Porch",
  "banner": {                       // self-fitting hero
    "image": "/local/images/Porch_Render.jpg",
    "height": "230px", "min_height": "150px",
    "show_time": true,
    "rooms_screen": "rooms"         // tapping the title opens Rooms
  },
  "grid": { "columns": 1 },
  "sections": [
    { "hero_label": "Activities", "tiles": [ /* activity tiles */ ] },
    { "hero_label": "Presets", "title": "Presets", "columns": 3,
      "tiles": [ /* preset icon squares */ ] },
    { "hero_label": "Devices", "title": "Devices",
      "tiles": [ /* device tiles + a summary nav card → comfort */ ] }
  ]
}
```

`hero_label` puts the section in the hero jump strip (scroll-spy
highlights the active one). A section's `columns` overrides the screen
grid — that's how Presets are a 3-up icon grid inside a 1-column page.

## Watch TV page

`screens.tv` — the activity screen both TV activities share:

```jsonc
"tv": {
  "name": "Watch TV",                          // title shows "Porch · Watch TV"
  "context": { "media_player": ..., "dpad": ..., "volume": ..., "volume_level": ... },
  "dpad_passthrough": "$context.dpad",         // physical D-pad IS the device D-pad
  "sections": [
    { "tiles": [
      { "id": "t_np", "type": "media", "entity": "$context.media_player",
        "trailing": { "icon": "material:apps",
                      "action": { "navigate": "apps" } } },   // Apps drawer
      { "id": "t_tr", "type": "transport", "entity": "$context.media_player" },
      { "id": "t_btns", "type": "buttons", "entity": "$context.dpad",
        "only": "physical_dpad",               // hardware remotes only
        "buttons": ["info", "menu", "back", "home"] },
      { "id": "t_pad", "type": "dpad", "unless": "physical_dpad" },  // browsers only
      { "id": "t_vol", "type": "volume", "entity": "$context.volume",
        "level_entity": "$context.volume_level" }             // ARC split
    ]},
    { "title": "Devices", "columns": 1,        // devices = full-width rows
      "tiles": [ /* media tiles; ⚙ trails are AUTOMATIC */ ] }
  ]
}
```

The same page serves Watch Fire TV and Watch Smart TV because the
ACTIVE activity's `context` overlays the screen's — including
`dpad_commands` (Fire TV `UP` vs Samsung `KEY_UP`). `$context.<slot>`
is the only substitution in the whole system.

## Activities (and why tiles light up)

```jsonc
"activities": {
  "watch_firetv": {
    "name": "Watch Fire TV",
    "start": "script.activity_watch_firetv",   // HA does the orchestration
    "screen": "tv",                            // navigate here on start
    "confirm_end": true,                       // red two-press confirm
    "context": { ... }                         // overlays tv screen context
  }, ...
}
```

`global.activity_select` names the minted
`select.harmonium_<room>_activity` the integration owns (legacy
`input_select` still accepted); tiles bind their lit state to it.
Select = start/open; hold or power = end.

## Device detail pages (GENERATED — zero config)

Tap any device tile's ⚙ zone → `detail:<entity_id>`. The engine
composes it from a per-domain recipe (power/stepper/chips; covers get
Open·Stop·Close + a vertical position slider), and the option pills
come from the entity's own attributes (`hvac_modes`, `source_list`…),
so they always match the hardware. A tile can override with
`trailing: {...}` (Now Playing → Apps) or suppress with
`trailing: false`.

The ONLY config that touches detail pages is per-entity quirks:

```jsonc
"entity_options": {
  "cover.maestroscreen_04_fr": { "invert_position": true }
  // display reads deployment: retracted = "Closed · 0%".
  // Services are never inverted.
}
```

## Device profiles (how the Astrion differs from a browser)

```jsonc
"devices": {
  "default": { "capabilities": ["touch", "pointer"] },
  "astrion": {
    "fully": true,                             // auto-selected under Fully Kiosk
    "capabilities": ["physical_dpad", "physical_volume", "touch"],
    "keymap": { "Tab": "down", "+": "vol_up", "[": "back", ... }
  }
}
```

Tiles opt in/out per capability (`only` / `unless`) — that's why the
on-screen D-pad ring exists in browsers but not on the remote, and the
button bar exists on the remote but not in browsers.

## Apps page

`screens.apps` — a 3-column grid of `preset` tiles, each firing
`media_player.select_source` on `$context.media_player`. Presets on
the home page additionally carry `"activity": "watch_firetv"` —
ensure-activity: pressing Netflix from a cold room starts the whole
activity first, then launches the app.

## What is NOT config (engine doctrine)

Back (status-bar chevron), the home ladder, hold-power = All Off,
touch-never-intercepted passthrough, detail compositions, spatial
focus, gesture timings — these are engine behavior, deliberately not
configurable per-screen, so every page behaves identically.
